## Как запустить

Нужны [Git](https://git-scm.com/) и [uv](https://docs.astral.sh/uv/).
Python отдельно ставить не нужно — его поставит uv.

```bash
git clone git@github.com:ВАШ_ЛОГИН/prime-monitor.git
cd prime-monitor
uv sync
```

Доступ к учебной базе выдаёт бот курса по команде `/db`. Полученную строку
подключения кладём в `.env`:

```bash
cp .env.example .env
# и вписать в .env строку из бота
```

Проверка, что всё встало:

```bash
uv run python -c "from prime.config import get_engine; print(get_engine().connect().execute(__import__('sqlalchemy').text('select current_user')).scalar())"
```

Отчёт на заданную дату после настройки `.env`:

```powershell
uv run prime report --date 2026-06-10
```

Дата отчёта исключается из расчёта. Команда показывает метрики за предыдущие сутки
и последние семь завершённых суток UTC, разложение выручки и причины пропуска
показателей. Журнал запуска сохраняется в `logs/prime.log`.

Запуск JupyterLab:

```bash
uv run jupyter lab
```

## Что здесь считается

Основной отчёт показывает семь метрик по клиентскому сегменту за предыдущие сутки
и за последние семь завершённых суток UTC.

| Метрика | Расчёт за период | Для чего |
|---|---|---|
| Выручка | Сумма платежей со статусом `success` | Следить за доходом от подписок |
| Успешные платежи | Число платежей со статусом `success` | Следить за объёмом списаний |
| Средний платёж | Выручка / число успешных платежей | Видеть изменение среднего размера списания |
| Активные подписки | Число действующих подписок на конец последнего дня периода | Следить за размером базы |
| Новые платящие клиенты | Число уникальных владельцев подписок, чей первый наблюдаемый успешный платёж пришёлся на этот период | Видеть приток новых плательщиков |
| Доля неуспешных списаний | `failed` / (`success` + `failed` + `refunded`) | Замечать проблемы со списаниями |
| Доля оттока | Число завершений среди подписок, активных на начало периода, / размер этой когорты | Следить за потерями подписок |

Поиск первой оплаты использует всю доступную историю до конца периода. Оплаты за
пределами истории ПРАЙМ и в пропущенных выгрузках могут остаться незаметными.
Платёж со статусом `refunded` считается ранее прошедшей попыткой списания и
входит только в знаменатель доли ошибок. За неделю долю считаем по суммарному
числу попыток. При пропуске данных или нулевом знаменателе выводится причина.
Число завершений по-прежнему доступно в витрине с разбивкой по каналам.

## Внешние данные

Курс USD/RUB [Банка России](https://www.cbr.ru/development/SXML/) показывает
валютный фон на дату отчёта. В отчёте также выводится дата начала действия курса,
которая может отличаться в неторговые дни. Выручка ПРАЙМ рассчитывается в рублях.

Для оценки движения рынка рядом с недельными метриками показываем
[индекс Мосбиржи IMOEX](https://www.moex.com/ru/index/IMOEX). Через ISS берём последние
доступные закрытия не позднее D−1 и D−8, где D — дата отчёта, и показываем даты
торгов и процент изменения. Индекс даёт рыночный контекст. Причины изменения
выручки оцениваем по данным о платежах ПРАЙМ.

Мосбиржа использует сертификаты НУЦ Минцифры. Если запрос к ISS завершается
ошибкой TLS, в PowerShell из корня проекта сохраните официальный сертификат
в локальную папку данных:

```powershell
New-Item -ItemType Directory -Path data -Force | Out-Null
Invoke-WebRequest -Uri 'https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt' -OutFile 'data/moex-ca.pem'
```

Этот файл используется только при запросах к ISS. Другой путь можно указать
в `PRIME_MOEX_CA_BUNDLE`. Инструкции по сертификатам приведены в
[сообщении Мосбиржи](https://www.moex.com/n103530).

Запросы ограничены тайм-аутом. При временном сбое выполняется повторная попытка.
Если источник недоступен, ошибка записывается в журнал, а отчёт показывает метрики
ПРАЙМ и отметку о недоступности внешнего показателя.
